# 土豆片 · TodooCard for SiYuan

> 在思源笔记里扫描、配对 TodooCard 墨水屏卡片，把图片直接发到 528×792 的屏幕上。

当前版本 **0.3.0** · 仅 macOS 桌面端 · MIT License

发送与图像转换复用上游 [Sunbelife/TodooCard_Skills](https://github.com/Sunbelife/TodooCard_Skills)。本插件不重写传图管线，只负责运行环境、核心安装、设备管理和思源内的操作界面。

## v0.3.0 亮点

- **卡片排版**：在插件里填标题、日期和一句话，用「整图标题 / 留白图文 / 照片墙」三种版式生成 528×792 卡片，预览即发送画面。
- **只有照片墙用多图**：其余版式固定单图，添加、Bing 壁纸、粘贴截图都会替换当前图片；照片墙支持 2–6 张排序与移除。
- **文字可整体开关**：关闭后只发纯图，重新打开会保留已填内容；Bing 每日壁纸重复点击可在最近 8 天之间切换。
- **图片操作就近摆放**：添加图片、Bing 每日壁纸、粘贴截图和清空都放在左侧预览说明下方，不再悬浮标签遮挡画面。
- **不抖出彩色噪点**：排版图只用面板原色黑 / 白 / 黄绘制，先渲染成卡片再交给上游转换，避免文字抗锯齿产生杂色。

## 核心特性

### 环境引导，而不是把报错丢给用户

插件会检查 `swiftc`、`python3`、`/usr/bin/sips` 和 macOS 平台四项条件。缺什么、怎么补，都写在面板里；一键安装后会每 4 秒自动复查，最多等待 10 分钟。安装过程仍需在 macOS 系统弹窗中确认，这是系统安全策略，插件不会绕过。

### 核心按需下载，安装可追溯

核心不随插件包分发。首次使用时从钉死的上游 commit 下载源码 tarball，校验固定 SHA-256 后解压，再以整目录替换的方式安装。下载线路只是传输通道，不改变校验结果；安装记录会保存来源、commit、实际摘要和安装时间，方便排查。

### 面向墨水屏的完整图片流程

支持 JPG / PNG / HEIC / TIFF / BMP / WebP 选择、Finder 拖入、剪贴板截图粘贴，可向右旋转 90°。2:3 取景框实时裁切，调用上游转换后展示 v157+ / legacy payload 大小，并把 528×792 的 4bit 位图解码成六色预览，发送前就能看到最终效果。

图片页另有 **卡片排版** 模式：填写标题、日期和一句话后，用 **整图标题 / 留白图文 / 照片墙** 三种版式直接生成 528×792 卡片。照片墙使用 2–6 张图片，可排序与移除；其余版式只用一张图片，添加图片、Bing 每日壁纸与粘贴截图会替换当前图片，相关按钮都放在左侧预览说明下方。「文字」可以整体关闭，只发纯图；Bing 壁纸重复点击可在最近 8 天之间切换。圆角、边框、底部信息带和留白都可调，排版图只用面板原色绘制，避免六色抖动产生彩色噪点。排版模式不读取、不展示 EXIF 信息。

### 设备扫描与多设备管理

默认只显示 TodooCard 兼容设备（manufacturer `0x5053` + screen `0x134C`），可关闭过滤查看全部；支持信号/名称排序、搜索、配对窗口筛选和已配对筛选。备注名、配对时间按设备 UUID 持久化；已配对设备即使当前没被扫描到，也能直接探测或按 UUID 发送。

### 多选批量发送

图片页底部可勾选多台目标卡片，一次发送到多台设备；发送前展示目标清单，只有收到卡片的 `0x05/0x08` 刷新确认才视为成功。

### 数据独立于思源同步

插件设置、配对记录和核心都放在思源工作区之外，不参与云端同步，也不会被旧副本覆盖。

## 快速开始

1. 安装并启用插件，点击顶部栏「土豆片 · TodooCard」图标。
2. 完成 **环境检查**。缺少命令行工具时点 **一键安装运行环境**，在系统弹窗中确认；也可以在终端执行 `xcode-select --install`。检查通过后 **下载核心** 解锁。
3. 点击 **下载核心**。国内网络慢时先把「下载线路」切到 `gh-proxy.com` 或 `ghproxy.vip`。
4. 切到 **设备**，点 **扫描设备**，选中卡片；首次连接按提示长按卡片背面按钮完成配对。
5. 切到 **图片**，选择/拖入图片或粘贴截图，调整取景框，点 **生成预览**；也可以切到 **卡片排版**，添加多张图片或 Bing 每日壁纸，填写文字后用三种版式生成卡片。
6. 勾选目标卡片，点 **发送到卡片**，核对清单后确认。

配对与发送都需要卡片在附近并保持唤醒。扫描只列出兼容设备；配对窗口关闭时，需要先长按卡片按钮重新进入配对模式。

## 环境要求

- macOS（Apple Silicon / Intel）
- SiYuan ≥ 3.0.1，桌面端
- Xcode Command Line Tools（提供 `swiftc` 与 `python3`）
- 系统 `/usr/bin/sips`
- 首次扫描时允许思源使用蓝牙（系统设置 → 隐私与安全性 → 蓝牙）

Command Line Tools 下载包通常为几百 MB 到 1 GB 出头，安装后占用约 1–3 GB，具体随 macOS / Xcode 版本变化。`python3` 由 Command Line Tools 一并提供，不需要单独安装。

## 设备与配对

- **扫描**：一次扫描约 30 秒；可随时停止，结果保留在当前面板。
- **筛选**：默认只显示兼容设备；可切换「仅兼容」、按配对状态过滤或搜索名称/UUID。
- **配对**：按设备 UUID 记录备注名和配对时间；配对前提示长按卡片背面按钮（新固件 5 秒 / 旧固件 10 秒），配对窗口最长 60 秒。
- **探测**：已配对设备可直接验证加密连接并读取电量；未配对时上游会返回明确错误，插件不会误报成功。

## 数据目录

默认位置：

```text
~/Library/Application Support/SiYuan/todoocard/
├── state.json        # 设置、设备备注、配对记录、上次选择
├── skill/            # 上游 Skill 副本（可重新下载覆盖）
├── skill-meta.json   # 来源、commit、SHA-256、安装时间
├── tmp/              # 下载/解压临时目录
├── cache/            # HEIC 等预览缓存
└── legacy/           # 旧版插件设备备注备份（如有）
```

该目录位于思源工作区 `data/` 的上一级，不在思源同步范围内；插件不使用 `saveData` / petal 存储，因此插件信息与配对信息不会被云端旧副本覆盖。

调试时可用环境变量 `SIYUAN_TODOCARD_HOME` 覆盖数据目录（测试用）。

## 核心来源与下载策略

- 默认来源：`https://github.com/Sunbelife/TodooCard_Skills/commit/81f61e10c60ff0e7199749c67d090bb74252fd66`
- 默认来源的 tarball SHA-256 固定为 `3fdde5a150dd967687af0e250d163b1f36ea378b1e13026f2bb6abe7fe7ce869`；直连或加速线路下载后都会先比对，不一致就拒绝安装。
- **不会自动跟随 `main`**，也不会自动下载；必须点一次「下载 / 更新核心」。
- 更新上游：在「设置 → 核心来源」把地址改成新的 commit 或 `main`，保存后点「下载 / 更新核心」。改成其他来源后没有可预知的固定摘要，只记录实际 SHA-256。
- 下载线路可选：直连 GitHub（默认）、[gh-proxy.com](https://gh-proxy.com/)、[ghproxy.vip](https://ghproxy.vip/)。后两者是第三方加速服务，不是上游官方镜像，可用性和隐私策略由各自服务决定；插件只把原始 codeload 地址拼在它们后面。
- 上游仓库没有 LICENSE，本插件**不重新分发**上游源码；只在用户本机按需下载。
- 下载后记录 tarball SHA-256 和解压出来的目录名（如 `TodooCard_Skills-<sha>`），便于追溯。

## 开发

```bash
npm install
npm test          # vitest：解析、状态存储、路径、Skill 安装、图片校验、payload 预览
npm run build     # 生成 dist/ 与 package.zip
npm run make-link # 把开发构建软链到思源插件目录
npm run dev       # watch 构建到思源插件目录
```

构建后手动安装：

```bash
unzip -o package.zip -d "$HOME/Library/Application Support/SiYuan/data/plugins/plugin-todoocard"
```

## 已完成的真机验证

- 单元测试 82/82 通过；TypeScript 检查与生产构建通过。
- 在 SiYuan 3.8.10（macOS）中安装并加载，顶部栏入口、引导页与 **图片 / 设备 / 设置** 三页签正常；默认打开图片页。
- 首次引导（临时空状态目录）：环境未通过时「下载核心」锁定并说明原因，通过后解锁；选择 `ghproxy.vip` 线路完成首次下载，`skill-meta.json` 记录 SHA-256 `3fdde5a1…`，与钉死值一致。
- 把渲染进程 PATH 临时指向不存在的路径模拟缺少命令行工具：引导页和设置页都显示「一键安装运行环境」，所有「下载核心」入口禁用；恢复 PATH 并复检后按钮解锁。
- 在设置页选择 `gh-proxy.com` 重新下载核心：下载地址为 `https://gh-proxy.com/https://codeload.github.com/...`，SHA-256 校验通过并原子替换成功。
- 一键安装会调用 `/usr/bin/xcode-select --install`；本机已安装 Command Line Tools，验证了「already installed → 等待并自动复查」分支，未在一台未安装 CLT 的干净机器上重装系统工具。
- 真实 BLE 扫描：一次扫描发现 36 台设备，其中 2 台 TodooCard 兼容设备（`519D2FA1…` / `C3B1E61E…`）；备注名持久化、多设备切换正常。
- 剪贴板截图粘贴、2:3 取景、上游转换与 528×792 六色 payload 预览正常；模拟 10 台已配对设备时，图片页高度不随列表增长，发送按钮始终可见。
- 提示统一为面板内浮层（toast）：未选图片、未生成预览、未选目标时不会拉长页面。
- 已配对但当前未扫描到的设备可直接 **探测**；配对仍要求设备处于扫描/配对窗口内。
- 未配对时探测/发送会返回上游的明确错误（`The secure bond is unavailable` / `Disconnected`），不会被误报为成功。

完整配对与发送仍需在卡片上长按物理按钮并允许 macOS 蓝牙配对提示；这是上游协议要求，插件不会绕过。

## 许可与限制

- 本插件代码以 MIT 许可证开源。
- 仅支持 macOS 桌面端（上游 Swift CLI 依赖 CoreBluetooth 与 `swiftc`）。Windows / Linux 暂不支持；待上游提供可用的 Windows 核心后再评估。
- 上游 Skill 不随本仓库或 `package.zip` 分发，只在用户本机按需下载。
